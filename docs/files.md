# File behavior

Upload one file of any type per browser session through the UI or `POST /api/document`. There is no application-enforced upload size limit; large requests can exceed browser/server resources, and multipart parsing may temporarily spool uploads to disk. Original bytes stay in server session memory for `GET /api/document/download`, which forces attachment download and `nosniff`. Replacing or deleting (`DELETE /api/document`) clears that session's attachment and edited copy, but not saved chat history. User names and chat turns (including citation titles and URLs) live in PostgreSQL and survive restarts. Each browser cookie tracks the selected user; selecting another user clears temporary uploads and generated files. Sessions and temporary files expire after 12 hours of inactivity or on server restart. Raw uploads are not copied into `documents/`.

For chat context, `.docx` paragraphs/tables and UTF-8 text files (`.txt`, `.md`, `.csv`, `.json`, `.xml`, `.yaml`, `.yml`, `.html`, `.css`, `.js`, `.py`, `.log`, `.ini`) are supported. All extracted text and the last 12 messages are included per turn. There is no application character cutoff, but large files can exceed the model or gateway context limit, increase cost and latency, or cause requests to fail. PNG, JPEG, GIF, WebP, and BMP are resized to JPEG for a vision-capable model. Other binary files (including `.exe`) are downloadable unchanged but never executed or interpreted. Unreadable files are shown as such, not described as analyzed.

When asked to edit an uploaded UTF-8 text file or `.docx`, the agent can call `edit_uploaded_file` to replace one exact, unique passage. It operates on a separate in-memory copy; `GET /api/document/download` still returns the untouched upload, while **Download edited copy** (`GET /api/document/edited`) returns the revised file. Further edits apply to the edited copy. The edited text becomes the chat context for subsequent turns. Editing is refused when the target is missing or ambiguous, or the file type is unsupported. Very large files can still exceed server memory or model limits. Word edits replace text within a single paragraph or table cell and try to preserve other runs/formatting. Replacing or deleting the upload clears its edited copy. The app never writes back to a local file on disk.

When asked to create a file, the agent uses the session-bound `create_text_file` tool. Generated formats: the UTF-8 text extensions above, `.docx`, `.pdf`, `.xlsx`, `.pptx` and `.zip`. `.docx` and `.pdf` accept plain text or JSON `{"blocks":[{"type":"heading","text":"Title"},{"type":"paragraph","text":"Body"},{"type":"table","rows":[["A","B"]]}]}`. `.xlsx` takes `{"sheets":[{"name":"Sheet1","rows":[["A",1]]}]}`; `.pptx` takes `{"slides":[{"title":"Title","body":"Text"}]}`; `.zip` takes `{"entries":[{"name":"notes.txt","content":"Text"}]}` (safe text entries only). The files are encoded with format-specific libraries, not renamed text. There is no application-enforced size limit for generated files; very large tool inputs or generated files can still exceed model, gateway or server memory limits. Only the most recent generated file is kept in session memory and available from `GET /api/files/download` until replacement, expiry or restart. Images and unsupported formats (including executables, audio, video and arbitrary binary formats) are not generated; each would need a dedicated safe encoder or service. Review generated source code before running it.

Tavily search can be enabled separately for current or externally verifiable questions. The agent chooses whether to search, but the tool sends only the user's current question to Tavily; it cannot send uploaded file data. For file-only questions, it should answer from the file without searching. When search returns results, the chat API appends source URLs to its `answer`; the browser displays the same sources as clickable links alongside the plain answer, and they persist in PostgreSQL chat history. No search means no web citations. Links indicate retrieved evidence, not automatic fact checking.

This is an unauthenticated local demo. Do not bind it to a public interface.
