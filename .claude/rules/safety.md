# Safety and validation

- Never print, copy into source files, or commit secrets from `.env` or user documents in `documents/`.
- Keep FastAPI using Deep Agents (`create_deep_agent`), uploaded document context, and optional Langfuse tracing. No terminal interface is required. Langfuse is for explicit chat answer/model/tool observations and feedback scores, not automatic HTTP or internal FastAPI spans. Guest turns are traced only with `LANGFUSE_TRACE_GUESTS=true` (default false, enabled on this machine; on 11/11 the operator removed the guest notice box, so no separate tracing notice is shown). The Langfuse session ID must be the random `s-…` `ChatSession.session_id`, never the login cookie or guest token. Keep healthchecks and polling untraced; `LANGFUSE_EXCLUDED_ROUTES` defaults to `/*` for automatic request telemetry and must not disable explicit chat tracing. Do not change Docker healthchecks to solve tracing noise.
- Optional `.workspace/` upload inspection defaults off; guest exports require the separate `WORKSPACE_EXPORT_GUESTS=true` opt-in. The operator approved persistent exports for accounts and guests on this machine via ignored `compose.override.yaml`. Keep snapshots Git-ignored, directories 0700 and files 0600; never export binary/image bytes, credentials or vectors. Snapshots survive guest cleanup and database deletion and require operator cleanup; disclose this guest-retention exception. Do not enable disk export on other installations silently.
- Keep browser uploads in memory and sessions isolated; do not expose this unauthenticated local demo on a public interface.
- Disable live embeddings in offline backend tests with `--env EMBEDDING_MODEL=`; fake-provider tests enable their own model. Also pass `--env WORKSPACE_EXPORT_ENABLED=false` so test uploads never write snapshots into the real `.workspace/`; workspace tests enable export into their own temporary directory. Large-file page text and search queries go to the configured embedding provider when enabled, including backfill of old files; never silently bypass the configured gateway.
- Document source text must render only as escaped plain text, never HTML or Markdown. Source IDs never grant access: require the active owned conversation, a persisted assistant reference and an existing upload. Bind citations to immutable read-time revision text; keep document `[D1]` and web `[W1]` markers separate and filter unknown/incomplete markers in streamed and stopped answers.
- Generated HTML preview is distinct from citation text: keep its allowlist sanitizer, no-permission iframe sandbox and restrictive CSP; never enable script/same-origin/navigation privileges. Bundle PDF renderer/worker assets locally and do not expose interactive PDF scripts/forms/links. Generated preview endpoints must check active conversation ownership, stored file membership and input/output size limits; downloads remain unchanged.
- Completion work is phase-by-phase; stop after each phase and report, with no commit. New-upload limits must not delete or block access to existing files. All provider timeouts must remain configurable with slow-network defaults. Cleanup must be manual only with dry-run, confirmation and backup recommendation. Backups stay Git-ignored/private and contain user data and password hashes. Final acceptance must explicitly verify message/file-content Langfuse redaction and no `/health` traces; embeddings work since 11/11 through the gateway as `nano/text-embedding-3-small`; keep using the configured gateway.
- Live tracing acceptance is explicitly gated by `AUDIT_LIVE_TRACING=1` in `tests/audit_tracing.py`: synthetic message/file/tool sentinels, full nested observation read-back including expanded metadata and bounded health window with exporter controls. Never infer redaction from config alone or call isolated-worker masking proof of private live traces when `LANGFUSE_TRACE_CONTENT=true`. Do not change runtime content tracing or embedding provider without separate approval; see `docs/acceptance.md`.
- Host operator storage/recovery is `scripts/storage.py`, never an HTTP/agent tool. Snapshot cleanup must select exact IDs, default to dry-run and require typed selection-bound confirmation; tests delete only synthetic fixtures. Backup configuration only with explicit `--include-config`, keep 0700/0600 permissions, and verify only trusted backups in network-isolated tmpfs PostgreSQL with no production mounts. Never run broad prune or production restore as part of verification. Mount `scripts/` read-only for backend unit-test discovery; see `docs/storage.md`.
- Prefer Docker validation: rebuild with `docker compose up -d --build`, run `python -m unittest discover -s tests` in a temporary app container with `tests/` mounted read-only, and smoke-check the running web app. See `docs/setup.md` for exact commands. Host Python environments are optional and are not kept in the cleaned workspace.
